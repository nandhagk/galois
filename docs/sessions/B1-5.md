### Review notes for this session

The F1 round 5 reviewer supplied these notes for the proofs.

- The plan gives `located` no cost. `T6a_rstep_credit` must absorb the upkeep of the map from
  earlier keys to current keys, on moves and on merges, within `k_active * entry_weight`.

- `F_wmark_index` holds for every slot code `s`, and `I.next` is at least 1. With no
  declarations and no slots, `wmark (init [] [])` must still be at least 1, so the
  implementation records the counter of the empty index in `index_counters`.

- `T_insert_steps` and `T_remove_steps` pay `fold_left` one call per cell beyond the step
  bounds. The session chooses `k_walk` above what `T_walk_ends` needs, so that the slack pays
  these calls.

The F1 round 10 reviewer supplied these further proof notes.

- `T_index_le` needs slot `s` within `O(log s)` calls, and `T_put_amort` pays
  `slots_of db f + 1` slot updates. A slot tree ordered by `s` fails for interleaved
  functions. A static table from `s` to a group rank and an offset, with a separate rank
  order for declared functions, meets both bounds. `T_init_le` needs the table built in
  linear time.
- `UNION_FIND_LAWS.card_union` allows `card` to grow by 2 on every union. The database must
  call `UnionFind.union` only on distinct roots, so that `card` stays below `3 * ids db`
  and `T_find_le` and `T_union_amort` hold.
- `union_same` holds without allocation, so `union` must link unallocated identifiers. The
  `DatabaseCode.union` placeholder returns the database unchanged and fails `union_same`.
- The reuse branch of `make_spec` demands `db' = db`, so `make` must discard the compressed
  forest that `UnionFind.find` returns.
- Keeping `located` within the repair budget needs stable row identifiers merged by size.
  Their chains then have depth at most the arity times `log2 (ids db)`.
- A slot whose permutation omits positions projects two rows onto one tuple. Removal needs
  a count per tuple, so that `inv_on` keeps the index equal to the projection of the rows.
- `F_wmark_index` holds for `init [] []` only if `index_counters` contains 1, because
  `I.next I.empty = 1`.
- `T_find_le`, `T_lookup_le` and `T_init_le` have no plan lemma. They follow directly from
  the union-find and map contracts.
- `T_run_ge` forces `advance` of the join to pass over all columns without an early exit.

## 3. How to read a Sig and its plan

- `FooSig.v` separates operations, derived definitions, functional laws, time contracts
  and proof plans into its `FOO_OPS`, `FOO_SPEC`, `FOO_LAWS`, `FOO_TIME` and `FOO_PLAN` layers.
- `Foo.v` implements `FooCode <: FOO_OPS`, `Foo <: FOO` and `FooT <: FOO_ALL`
  through an `Include` chain.
- Your proof targets are the `Admitted` lemmas in your files, tagged `CONVERT`, `STUB`,
  `SIG-QUESTION`, `PLAN-DEFECT` or `OPEN`.
- A `PLAN` lists functional lemmas before time lemmas and ends at a contract.
  Prove them in order. Each lemma may use earlier lemmas. Choose values for `k_*` and `c_*`.
- A `Parameter` of another component's signature may be used before it is proved. Your tests may
  run only code that exists in this base.
- Time functions, callback companions, `c_*`, `k_*` and time-bound potentials have type `N`.
  Sizes keep their declared types. Wrap each largest `nat` size expression in `N.of_nat` once
  when it enters a bound. Use `%N` on time statements and an `N`-valued size for `bigO`.
- Use Argent's `time_step`, `time_cbn` and `time_pose`, then `lia` or `nia`, for time proofs.
  Plain `cbn` and `simpl` unfold binary arithmetic on numerals. The
  [session time rules](../design/rules.md#10-timefun-in-the-timed-layer) govern these proofs.
  Read time statements in the archival design documents through the binary-time rule in
  [section 8](../design/rules.md#8-writing-a-sig-file).
