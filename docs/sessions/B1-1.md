### Review notes for this session

The F1 round 5 reviewer noted that raw carrier sets need not be `wf`, so a stored key can
differ from its code and `nodes` can exceed `weight`. The current sizes count the skeleton as
well as the weight. The reviewer also suggested choosing `c_lat` at least about
`c_set * (2 * nodes U.u + 1)` for the bounded set time bounds.

The F1 round 10 reviewer supplied these further proof notes.

- `MaySetT.size` and `BoundedSetT.size` now count both `S.nodes` and `S.weight` on raw
  carriers. A raw set need not be `S.wf`, so `S.nodes <= S.weight` is unavailable. A set
  storing key `1` at code `2^1000` illustrates why the skeleton must be counted.
- `MapLatticeT.size` now includes `M.nodes` alongside the value sizes. One binding at a
  1000-bit key illustrates why the skeleton is needed for `T_leb_le`.
- `T7_fold_work` uses the summed `fold_work` and cannot follow from the uniform
  `T6_fold_path`. It needs a direct proof.
- `T_loopN_amort` needs `c_loopN` to cover one loop call, one `loopN_step` call and the
  amortised `N.pred`. `HeapT` must pick `k_credit` above `k_remove` plus that constant.
- `HAS_MEET_TIME` prices `meet` with `L.c_lat`. No module today implements a separate
  `HAS_MEET_T` over an existing lattice, so the constant issue found for widening remains
  latent there.

The F1 round 13 reviewer supplied these further proof notes.

- `heap_tree_entries_into` uses a local `fix` over children. Prove
  `heap_tree_entries_into tr acc = heap_tree_entries tr ++ acc` by nested induction first.
  Use this append lemma in the proofs about `heap_valid` and `F1_pending`.
- Choose `c_lat` for `Dual`, `Product`, `Reduced`, `WithBot`, `WithTop`, `MapLattice`,
  `Sets` and `Bounded` from the parameter constants. Keep each at least 1 for `c_lat_pos`.

## 3. How to read a Sig and its plan

- `FooSig.v` separates operations, derived definitions, functional laws, time contracts
  and proof plans into its `FOO_OPS`, `FOO_SPEC`, `FOO_LAWS`, `FOO_TIME` and `FOO_PLAN` layers.
- `Foo.v` implements `FooCode <: FOO_OPS`, `Foo <: FOO` and `FooT <: FOO_ALL`
  through an `Include` chain.
- Your proof targets are the `Admitted` lemmas in your files, tagged `CONVERT`, `STUB`,
  `SIG-QUESTION`, `PLAN-DEFECT` or `OPEN`.
- A `PLAN` lists functional lemmas before time lemmas and ends at a contract.
  Prove them in order. Each lemma may use earlier lemmas. Choose values for `k_*` and `c_*`.
- A `Parameter` of another component's signature may be used before it is proved. Your tests may
  run only code that exists in this base.
- Time functions, callback companions, `c_*`, `k_*` and time-bound potentials have type `N`.
  Sizes keep their declared types. Wrap each largest `nat` size expression in `N.of_nat` once
  when it enters a bound. Use `%N` on time statements and an `N`-valued size for `bigO`.
- Use Argent's `time_step`, `time_cbn` and `time_pose`, then `lia` or `nia`, for time proofs.
  Plain `cbn` and `simpl` unfold binary arithmetic on numerals. The
  [session time rules](../design/rules.md#10-timefun-in-the-timed-layer) govern these proofs.
  Read time statements in the archival design documents through the binary-time rule in
  [section 8](../design/rules.md#8-writing-a-sig-file).

## 5. When stuck

- Leave a lemma `Admitted` after 20 minutes without progress. Keep its statement,
  add `(* OPEN: what is missing *)` on the same line and go to the next item.
- Prove a contract another way when its `PLAN` lemma is false or useless. Leave that lemma
  `Admitted` with `(* PLAN-DEFECT: reason, counterexample if any *)` on the same line.
- Stop work on a component when its public `LAWS` or `TIME` statement is false. Leave its
  implementation obligation `Admitted` with `(* SIG-QUESTION: reason *)` on the same line.
  Report the defect and move to the next component. Keep the signature file unchanged.
- Port the old proof named by a `CONVERT` tag. Renaming and unfolding are allowed.
- Never weaken a statement, add a hypothesis to a Sig lemma, or edit outside your paths.
